# Fairness guidelines

- Compare only capabilities supported by every included baseline.
- Use each external tool's documented APIs and recommended configuration.
- Do not deliberately choose inefficient settings for another project.
- Keep schemas, seeds, row counts, storage layouts, and queries constant where applicable.
- Separate statistical-fidelity tools from schema-from-scratch test-data tools in conclusions.
- Report licensing, hardware, optional dependencies, failures, and unsupported cases.
- Publish raw manifests and scripts with any reported measurements.
- Do not generalize one local fixture into a universal performance or quality claim.
